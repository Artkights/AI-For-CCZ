# godtype OllyDbg 教程与复刻版 6.6 山贼国庆版验证

## 结论速览

- godtype 的《如何使用 OllyDbg 修改曹操传引擎》适合作为“如何读旧式 x86 曹操传引擎”的方法教程，但正文地址属于原版或早期扩展引擎，不能直接作为 6.5、6.6 的补丁地址表。
- 本页把论坛三页、首帖列出的关联资料和本地离线备份归纳为检索线索，并对 `基底/复刻版6.6山贼 国庆/Ekd5.exe` 做了只读静态复核。目标文件 SHA256 为 `F36F9A3D06F3C4E52F32320FAE4633D0EADC9B7863F410EA7532B3C45E2ABF88`，下文简称“F36 样本”。
- F36 样本确认了四个可复用的结构锚点：人物记录为 `[004CEA00] + Data号 * 48H`，战术单位为 `004A7B20 + 战场编号 * 30H`，物品记录为 `0049F820 + 物品号 * 19H`，策略记录为 `004A3E77 + 策略号 * 61H`。
- `004927F0`、`00497AF8`、`00497750` 三个旧教程上下文基址在 F36 样本中仍有直接引用；这只能确认“该内存块仍被代码使用”，不能自动确认旧帖给出的每个字段名、数组容量和触发语义。
- 旧教程的单位公式 `004B2C50 + 编号 * 24H`、固定人物基址 `004A1B68`、可调用入口 `00407A09/00407AF2`、主动双击注入点 `00405CE6` 和代码空洞 `00485DD3` 均不能用于 F36 样本。其中部分已被当前代码明确否定。
- 本轮没有启动游戏、没有附加调试器、没有修改 `Ekd5.exe` 或任何基底资源。结论等级最高为“当前 SHA 已验证静态事实”，实际战斗行为、字段时序和 Hook 可用性仍需动态验证。

### F36 样本身份与静态分析范围

F36 样本是 PE32/x86，机器类型 `332`，映像基址 `00400000`，入口 RVA `000817E0`，映像大小 `00147000`。`.code` 区段 RVA 为 `00001000`、原始文件偏移为 `00000400`；PE 没有重定位目录。没有重定位目录不等于任意绝对地址都能跨版本复用，只说明该文件自身依赖固定装载布局。

只读静态流水线完成了机器提取，但没有完成人工语义审阅：

| 指标 | 结果 |
|------|------|
| 函数候选 | 3,648 |
| 指令 | 137,127 |
| 数据项 | 6,065 |
| 间接转移 / 未解析间接转移 | 2,330 / 390 |
| 未知字节 | 81,964 |
| 反编译失败 | 0 |
| 文件区域处理率 | 1.0 |
| 输入文件哈希复核 | 未变化 |
| 目标回归检查 | 通过 |
| 运行时验证 | `false` |

报告状态是 `partial-static-delivery-not-full-semantic-acceptance`。它能支持字节、指令边界、直接引用和 PE 布局事实，不能单独支持完整业务语义。

### 当前结构锚点

人物运行时记录访问函数：

```asm
004061E4  push ebp
004061E5  mov ebp,esp
004061E7  movzx ecx,word ptr [ebp+08]
004061EB  imul ecx,ecx,48h
004061EE  add ecx,dword ptr [004CEA00]
004061F4  pop ebp
004061F5  ret 4
```

因此当前公式是：

```text
CharacterRecord = [004CEA00] + DataId * 48H
```

战术单位访问函数：

```asm
004061F9  push ebp
004061FC  movzx ecx,cl
004061FF  imul ecx,ecx,30h
00406202  add ecx,004A7B20
00406209  ret
```

因此当前公式是：

```text
BattleUnit = 004A7B20 + UnitId * 30H
```

单位转人物与兵种字段还有以下静态链：`0040658F` 内部在 `00406592` 压入 `[ECX]` 后调用 `004061E4`；`00406610` 在 `00406613` 读取人物记录 `+2B` 的 BYTE；`0041DF70` 内部依次调用这两个转换步骤。

物品和策略记录访问函数分别给出：

```asm
004837C5  imul ecx,ecx,19h
004837C8  add ecx,0049F820

00484005  imul ecx,ecx,61h
00484008  add ecx,004A3E77
```

即：

```text
ItemRecord     = 0049F820 + ItemId * 19H
StrategyRecord = 004A3E77 + StrategyId * 61H
```

## 实现/使用方法

### 从旧教程迁移到当前样本的流程

1. **固定身份**：记录目标相对路径、文件大小、时间戳和 SHA256。任何一项变化都重新定位，不能沿用“同为 6.6”这一宽泛标签。
2. **保留原件**：只在可恢复副本上调试或写入；基底原件、备份和测试副本分别计算哈希，防止把旧测试文件误当发布文件。
3. **先做 PE 映射**：区分虚拟地址、RVA 和文件偏移，确认目标位于哪个区段及其读写执行属性。教程中的运行时地址不能直接当文件偏移。
4. **按结构或行为重定位**：组合使用常量、步长、基址引用、调用者、返回方式和周边原字节。例如人物函数的可靠特征不是单独的 `004061E4`，而是“16 位参数、乘 `48H`、加指针槽、`ret 4`”。
5. **确认入口与 ABI**：核对函数起点、所有调用者、栈清理、参数宽度、返回寄存器、被调用者保存寄存器和 EFLAGS。禁止把内部跳转或普通指令当 `CALL` 入口。
6. **审计 Hook 覆盖**：保存当前 SHA 下的原字节和完整指令边界；被覆盖指令必须在跳板中正确恢复；记录代码洞所有权、跳入地址、回跳地址和冲突补丁。
7. **分层验证**：先做静态字节与交叉引用复读，再在测试副本中用断点记录正样本、负样本、反击/连击/多目标等分支，最后才进行可回滚写入和完整战斗烟测。
8. **保存后复读**：重新打开修改后的文件，核对哈希、目标字节、PE 映射、跳转落点和未改变区域；失败时恢复备份，不在未知状态下继续叠加补丁。

### 使用三个上下文基址

`004927F0`、`00497AF8`、`00497750` 可作为 F36 样本的静态搜索锚点。正确的后续步骤是：

- 先枚举读写交叉引用并按物理攻击、策略、道具场景分组。
- 对候选偏移设置读取或写入断点，记录触发前后值、调用栈和当前行动类型。
- 分别采集单目标、多目标、失败、反击、恢复和状态类样本。
- 只有同一偏移在正负样本中形成闭环后，才把旧帖字段名提升为当前样本字段。

不能仅因某个函数引用了上下文基址，就把该函数命名为“伤害计算”“命中特效”或“目标数组构建”。基址引用只证明数据依赖，不证明完整业务职责。

## 风险与边界

- 本轮是静态验证，不是实机验证。没有启动游戏、没有断点命中、没有记录运行时寄存器/堆栈，也没有确认旧字段在 F36 样本中的实时取值。
- 静态流水线仍有 `390` 个未解析间接转移和 `81,964` 个未知字节，人工语义审阅数为 `0`。不能把“反编译成功”理解为“业务语义正确”。
- F36 样本与仓库旧 6.6 专题的 SHA 不同。即便多个结构函数地址恰好一致，也必须按当前字节重新确认 Hook 覆盖、代码洞和调用约定。
- “代码空洞”不是永久公共资源。任一版本更新、已有补丁、链接器布局或外部 DLL 注入都可能占用旧空白区；使用前必须确认整段字节、交叉引用、区段属性和所有权。
- 旧教程中的绝对地址、概率、状态位、表长和数组容量不能仅凭相似代码迁移。尤其是目标数组和上下文字段，错误写入可能越界或破坏回合状态。
- 没有重定位目录意味着该样本通常依赖 `00400000` 基址，但仍应在运行时确认模块基址；不能据此推导其它 EXE 具有相同布局。
- 本地静态报告目录被 Git 忽略，用于可重复分析和审计，不作为需要强制提交的大体积知识库内容；正式知识只收录可复核摘要和证据边界。
