# 布尔变量全量读写与紧凑存储（2026-11-09）

本次改动把布尔变量的原生存储识别、读取快照、单项保存、页面批量保存和全量归档统一到 `variable_storage.py`。工具根据已验证的基底布局决定可写范围，不再把固定的 4096 当作所有版本的真实容量。

## 已验证的原生布局

| 基底 | 原生存储 | 已验证编号 | 地址规则 | 保存规则 |
|---|---|---:|---|---|
| 6.6 位图基底 | 1 字节承载 8 项，MSB 到 LSB | 0..1535 可写；1536..2047 只读浏览 | `base + index // 8`，掩码 `0x80 >> (index % 8)` | 只修改目标位，保留同字节其他 7 位 |
| 已核验 6.4/6.5 基底 | 每项 4 字节 DWORD，非零为真 | 0..2047 可写 | `base + index * 4` | 只替换目标 DWORD，保留步长填充字节 |
| 未通过原生证据的旧版画像 | 格式或容量未确认 | 只读或不可用 | 不套用固定容量 | 禁止兼容模式绕过 |

6.6 的 `1536..2047` 位图空间仍没有独立的原生用途边界证明，其中 `2048` 起会覆盖人物 DWORD 表，因此不进入普通保存域。6.4/6.5 的 2048 项来自原生 getter/setter、剧本调用链以及保存/加载循环的 `cmp index, 0x800` 和每项 4 字节复制证据。6.1–6.3 在当前本地样本中没有足够的同等级证据，继续保持待核验策略。

## 存储和事务

`BooleanSnapshot` 以一段连续 `bytes` 保存原始存储，不再为每一行创建字典键和值对象。6.6 的完整可写域只需 192 字节，浏览域为 256 字节；旧版 2048 DWORD 使用原生 8192 字节布局。所有写入先在快照上合并同字节或相邻脏区，再通过带期望字节的比较交换事务提交。会话代号、布局变化、只读会话、外部改码、部分写入和写后复读失败都会阻止保存并保留原快照。

布尔归档使用 16 字节头（魔数、数量、CRC32）和 MSB 位打包载荷，只导出当前基底已经验证的完整可写域。导入先验证长度、数量、CRC 和尾部填充位，再对新鲜全域快照执行一次合并事务；导入文件不能写入保留位或人物表。

## 界面行为

变量页仍按 100 项分页显示。6.6 显示 `地址.位`，并在提示中给出实际地址、参考地址、物理位、掩码和原始字节。旧版 DWORD 保留普通地址显示。布尔表格和“保存”按钮的右键菜单提供“保存本页全部修改”“全量导出…”和“全量导入并保存…”。单行保存不会清除同页其他未保存编辑。

实现继续使用 CPython 3.8.10 x86、PyQt5/Qt5、QTimer、ctypes 和已有 Win32 API；没有引入 asyncio、高版本 Python 语法或 Windows 10 专用 API。

验证记录：紧凑存储模块 22 项、布尔界面 19 项、布尔画像 11 项通过；使用 FakeMemory 覆盖位图全部 1536 项逐位切换、保留位拒绝、人物表保护、旧版 DWORD 高字节冲突和归档校验。真实 Win7 SP1 环境和真实运行中游戏写入仍需在目标机器单独执行。
