## 可重复的只读发布诊断

诊断必须明确给出本地PID，使用OS只读进程句柄，不执行补丁、保存或远程调用：

```powershell
& '.\6.6扳手.exe' --attach-pid 12345 --diagnostic-output 'F:\验证\release.json' --diagnostic-exit
```

无诊断参数的正常启动不自动选择目标。自定义CSV保留现有六列格式；原有地址按参考VA解析，模块重定位由当前会话处理，页面显示地址及字段宽度以便核对。

## Windows 7 兼容性目标（2026-11-06）

目标矩阵为 **Windows 7 SP1** x86、Win7 SP1 x64（WOW64）、Windows 8.1、Windows 10 和 Windows 11。扳手与目标游戏均为 PE32/x86；高完整性目标需要同等权限的扳手。Win7 RTM、Vista 和 64 位目标游戏不在目标范围内。该矩阵是发布验收目标，不是已通过结果；此前引擎画像和游戏副本的验证不能推导出 Win7 实机通过。

构建基线固定为 **CPython 3.8.10 x86**；Python 3.8 是最后支持 Win7 的 CPython 版本线，3.8.10 是最后提供官方 Windows 二进制安装程序的版本。`requirements-win7-x86.txt` 锁定 PyQt5/Qt、psutil、pywin32、PyInstaller、Capstone 及传递依赖，并锁定 wheel 哈希。wheelhouse 提供离线二进制依赖和清单；默认安装使用 `--no-index --require-hashes`，避免解析到新版本。以该锁文件为实际版本来源，不在文档中维护另一份容易过期的完整版本表。

干净 Win7 可能需要 Win7 兼容的 VC++ x86 运行库和 Universal CRT。当前实现不检查 SHA-2/UCRT 补丁清单、不自动安装系统更新，也不保证在 Python/Qt 载入失败后仍可显示应用内提示。构建会检查 PE32/x86、Qt 平台插件、pywin32、Capstone 和嵌入业务模块，并按实际解释器布局收集附加运行库；官方 CPython 不要求存在 Conda 的 `Library\bin`。

构建入口为 `build_release.py`，`build_release.ps1` 仅包装调用；实际构建不依赖 PowerShell 的 `Get-FileHash` 或 `[type]::new`。Win7 自带 PowerShell 2.0 可直接运行 `build_32bit.bat`，该入口只调用同一个 Python 构建器。`--prepare-wheelhouse` 准备离线依赖，正常构建默认 `--format both`，也可指定 `onedir` 或 `onefile`。产物分别位于 `dist-win7/onedir/6.6扳手/6.6扳手.exe` 与 `dist-win7/onefile/6.6扳手.exe`；`--dist <目录>` 更改输出根目录。ZIP、`SHA256SUMS.txt` 和 `manifest.json` 随产物交付，`reports/<形式>/` 保存 `native-import-audit.json`、`source-consistency.json`、`startup-smoke.json`。临时构建文件默认位于 `build-temp-win7/`，可用 `BANSHOU_BUILD_TEMP` 调整。目录版是首选诊断形态；两种形式均需通过归档和启动烟测。`--skip-smoke` 会明确留下未执行启动验证的边界。

发布版的用户数据目录为 `%LOCALAPPDATA%\CaoCaoZhuan\Banshou`；缺少 `LOCALAPPDATA` 时回退 `APPDATA`，两者都不可用时使用当前用户主目录下的 `AppData/Local`，主目录无法确定时回退临时目录下的 `CaoCaoZhuan/Banshou`。`logs/startup.log` 与 `logs/compatibility-report.json` 记录启动结果；日志目录创建失败还可回退临时日志目录。迁移只复制目标尚不存在的 `DIY.csv`，保留源文件且不覆盖已有用户文件；中断时删除不完整目标，读取保留旧目录回退。显式 `--diagnostic-output` 写入调用者指定的位置。资源加载使用 Unicode 路径和 `LoadImageW`；Qt 平台插件从 Python 的实际 PyQt5 包路径设置，绕过 Qt5 在中文前缀上返回问号的 `QLibraryInfo` 路径。

启动接口 `collect_compatibility_report(check_native=False, strict=None)` 和 `format_compatibility_errors(report)` 提供 Windows 版本/service pack、Python 版本、进程位数、警告和错误。发行包严格拒绝 Win7 RTM、非 32 位解释器和非 3.8.10 Python；源码离线测试采用非严格模式，允许现代解释器和非 Windows 环境。依赖检查尝试载入 Qt、pywin32、psutil、Capstone 等模块及 Qt 平台插件，失败写入 JSON；Qt 导入失败仍可用原生 Win32 消息框提示。Python 启动前的 DLL 加载器失败无法由应用内报告捕获。目标 PE32/x86 与访问权限由附加流程检查；可选 API（例如 `GetProcessMitigationPolicy`）不可用时只记录诊断，不阻断 Win7 普通读写。

启动烟测通过 `--startup-smoke-output <JSON路径> --startup-smoke-exit` 执行。完成 Qt 事件循环回调、创建可见窗口、核对八页和三个资源文件后才写成功，随后正常退出；整个过程不附加游戏、不写游戏内存、不执行远程调用。进程存活或仅出现窗口不能替代成功 JSON 与退出码。

兼容性验收分三层：在无游戏的干净机验证启动和资源；用 `--attach-pid ... --diagnostic-output ... --diagnostic-exit` 做八页只读诊断；在隔离副本执行读写复读、回滚、远程调用、解绑和重新附加。矩阵需覆盖普通用户/管理员、中文路径、缺运行库、64 位目标和访问被拒绝等场景。Win7 实机结果尚需单独记录；模拟 OS 单元测试、现代系统启动烟测和只读诊断均不能替代真实 Win7 上的写入与战场行为验收。
